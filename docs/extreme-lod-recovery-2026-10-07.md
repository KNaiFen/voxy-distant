# 空缓存高速移动与瞬移：节点故障复现、修复和验证

## 结果与适用范围

基线提交 `dd21d22`（0.2.26），修复版本 `0.2.27-forge-1.20.1`。在真实 Forge 客户端与专用服务端上构造了空客户端缓存、热服务端缓存、下载中高速往返、连续瞬移、未缓存区域和渲染器重建场景。查出了三处持久状态错误，并完成修复及回归。

最终 320 和 1024 方块/秒场景在服务端允许生成缺失区块时，各检查点均满足目标精度；停止后网络、接收、网格及节点请求收敛，节点收缩与过期网格重建等待归零。GPU 可见节点采样中没有距相机 128 方块内的 L3/L4 节点。禁止生成时，未缓存区域可保留无数据列；额外静止检查和返回缓存区域仍能正常恢复。

测试使用 Voxy 0.2.15-beta、Forge 47.4.20、Embeddium 0.3.31、Java 21.0.7，没有启用光影。用户 DeceasedCraft 实例只读，本轮没有启动、修改或删除该实例的存档、配置、模组、缓存。测试以移动包驱动真实原版区块跟踪；没有安装用户的载具模组，不能声称覆盖完整整合包、Voxy SR/Shadows 或光影组合。

## 查明的故障

| 问题 | 复现证据与后果 | 最小修复 |
| --- | --- | --- |
| Voxy 父节点叶标志失配及 GPU 更新遗漏 | 空缓存 320 方块/秒、下载中急转，在约 7 秒内触发 `NodeManager.verifyNode:1581`，异步节点处理停止。三层真实节点树可分别复现子掩码归零收缩与网格淘汰后的父标志失配；展开路径则更新 CPU 标志但没有提交父节点 GPU 更新 | 在收缩及淘汰转换完成时更新直系父节点的标志；展开路径补齐 GPU dirty。最多检查 8 个直接兄弟节点，不递归修复或定时扫树 |
| 客户端残留的原版已加载标记挡住远程补齐 | 连续瞬移并回原点，区块 `(-19,-11)` 的诊断为 `loaded=true, actual=false, level=5`，捕获、网络与网格队列已经归零，仍不恢复 | 调度发现缺口且存在已加载标记时，将其放入现有捕获核验流程。主线程确认区块不存在后清除标记，经现有 unload 流程重新请求远景 |
| 服务端原版版本未持久失效，卸载后旧缓存复活 | 1024 方块/秒停止后有 165 列始终 level 5。`(-16,-1)` 服务端反复返回旧版本 `117396545720616317` 并判定 cache hit；客户端最新原版版本为 `117396559725530199`，所以正确拒绝。服务端内存版本已清理，持久缓存没有对应失效记录 | 首次分配原版发送版本时，同时加入已有 dirty 持久化批次。复用现有失效、刷新、窗口和节流流程；重复发送沿用同一版本 |

节点修复位于 VD 的兼容 Mixin，没有修改配套 Voxy 源码或依赖 JAR。客户端仍拒绝旧版本与过期网格，没有降低校验标准、吞掉异步错误或用假 L0 掩盖缺失数据。协议版本仍为 17，缓存格式不变。

测试中还查到持续真实更新：存档中的实体不断触发幽匿感测体，造成区块版本连续变化与快照重采集。用调用栈确认了 `SculkSensorBlock.activate/deactivate`，随后仅在独立测试存档的稳定性检查前清除非玩家实体，关闭新实体生成和随机 tick，并等待活动结束。这不是缓存版本错误。原始活动场景作为压力对照已经记录。

## 场景与成功标准

每轮删除独立测试客户端的 `.voxy`，服务端复用同一个已导入 4096 列的缓存。原版客户端距离 10，服务端视距 8、模拟距离 2；VD 半径 24、档位 `8:0,16:1,24:2`、窗口 512、接收预算 128 MiB、索引 256 MiB、接收占空比 0.9。Voxy 8 个服务线程、细分尺寸 64，`ingest_enabled=false`，验证远程接收与本地自动摄入已经解耦。

首个网格出现就开始移动，不等待下载完成。路线为区块 `(8,0),(-8,0),(8,8),(-8,-8),(-8,8),(8,-8),(0,0)`，重复 8 次、共 56 段。停止后检查，再重建渲染器检查。随后每隔约 2 秒依次瞬移 `(16,16),(-16,-16),(目标,0),(0,0),(目标,0)`；目标在该轮启动前没有 region 文件，也没有预导入 LOD。目标区将接收半径降为 12，移动 `(目标+4,4),(目标-4,-4),(目标,0)`，最后返回原点并恢复半径 24。

测试专用 `ExtremeMovementMixin` 只在独立服务端诊断参数开启时绕过原版移动速度回退，保证高速移动包实际进入服务端区块跟踪。服务端位置采样确认经过路线和目标坐标。这个 Mixin 和所有监测类均在 smoke source set，不进入安装包。

开启 `-Dvoxy.verifyNodeManager=true`、节点采样及 GPU 可见列表回读。节点采样只在节点所有者线程进行；检查时提交一个空请求批次，唤醒空闲线程完成原生完整性校验和新采样，避免将旧监测结果判为通过。要求无异步节点异常、接收异常，节点请求/收缩等待/过期网格重建为零，接收与网格队列空。允许生成时要求覆盖缺口为零；禁止生成时允许 level 5 无数据列，已经有数据的列仍须满足档位。GPU 检查针对已稳定场景，下载中的临时粗节点允许存在。

## 最终验证结果

| 验证 | 最终结果 |
| --- | --- |
| 320 方块/秒，空缓存，允许生成 | 路线与重建渲染器均为 1793 列完整；瞬移至 14336 方块外的新区域及当地往返为 441 列完整；返回原点 1793 列完整。所有节点等待归零，GPU 近处 L3/L4 数为 0 |
| 1024 方块/秒，空缓存，允许生成 | 路线与重建后 L0/L1/L2 为 `345/805/643`；瞬移至 10240 方块外的新区域和往返为 `334/107/0`；返回为 `406/846/541`。各阶段缺口 0、节点等待 0、GPU 近处 L3/L4 数 0 |
| 1024 方块/秒，禁止生成 | 瞬移至 16384 方块外的新区域，初次 40 列无数据；当地往返后及额外静止 20 秒均为 36 列无数据，其余 405 列精度满足。节点等待 0、GPU 近处 L3/L4 数 0。返回原点 1793 列完整 |
| 真实接收流程回归 | 单包/批包/unchanged、重复粗回复、迟到旧请求、Dirty、加载版本保留、残留已加载标记核验、会话切换通过。后台覆盖锁被持有时主线程 hook 检查约 69 微秒 |
| `runData -PclientSmoke` | 真实转换后的 Voxy 嵌套展开、收缩、淘汰、父节点 GPU 更新，L0～L4 摄入、过期拒绝、磁盘网格恢复、索引重建与 10000 次 mipper 对照通过 |
| 构建与现有测试 | `test smokeClasses build runData -PclientSmoke` 成功；现有 7 组、17 项测试零失败、零错误 |
| 专用服务端集成 | 生成与缓存、版本失效持久化、重复原版版本复用、队列/窗口/批包/取消、设置、维护、停止释放均通过；`INTEGRATION_PASS True EXIT 0` |

禁止生成的对照中，若原版曾加载后卸载的区块缓存已被较新版本失效，而它此时又不在服务端加载范围内，仍可暂时返回 unavailable；后台刷新或重新加载后能补齐。测试将这种无数据状态单独记录，不算已经有数据却卡在粗精度，也不声称禁止生成能够提供任意未缓存地形。

## 性能与消融审查

生产改动限定为三处状态维护：节点转换时最多 8 次 map 查询、发现被加载标记挡住的缺口时复用捕获核验、原版新版本加入现有 dirty 批次。没有新增生产线程、全范围周期扫描、网络消息类型、配置项或无限重试；原接收内存信用、请求窗口、生成节流和失效批量上限继续生效。首次原版版本持久失效可能增加必要的缓存刷新，这是保证较新原版数据不会被旧缓存覆盖的成本。

320 方块/秒最终轮预留内存峰值 33.36 MiB、接收队列峰值 406/512、请求峰值 204/512；1024 允许生成轮分别为 29.26 MiB、387/512、295/512；禁止生成静止对照轮为 29.62 MiB、356/512、290/512。各轮均收敛。GPU 同步回读和完整性校验只用于诊断，会增加开销，本报告不将这些运行的帧率当作生产性能提升证据。

消融后删除了临时 Dirty 调用栈 Mixin及调试输出环境，保留实际必要的嵌套节点、残留加载标记、服务端版本回归与可重跑的极端场景监测。没有改变遮罩、渲染精度算法或为没有实测收益的路径添加兜底。

## 重跑方法与交付

输入和 launch spec 的准备方式沿用 `docs/coarse-lod-recovery-2026-10-07.md`；复用已有 `build/benchmarks/lod-square256-cache128` 基线，按需重建小输入，不复制整套基线。普通服务端烟测会修改开发 classpath，重跑客户端前需生成带 `-PlodClient` 的启动参数。

```sh
./gradlew --no-daemon smokeClasses writeClientLaunch writeSmokeLaunch -PlodClient
python tools/coarse-recovery-check.py --mode request --variant request-check
python tools/coarse-recovery-check.py --mode extreme --variant extreme-320-cold --speed 320 --uncached-target 896 --generate-missing
python tools/coarse-recovery-check.py --mode extreme --variant extreme-1024-cold --speed 1024 --uncached-target 1024
./gradlew --no-daemon test smokeClasses build runData -PclientSmoke
./gradlew --no-daemon smokeClasses writeSmokeLaunch
python tools/server-smoke.py
```

复用游戏时，`--uncached-target` 必须选择该测试存档尚无 region 文件的区块坐标；脚本在启动前校验。`-cold` 后缀明确清理独立客户端缓存。每轮完成或中断后都应停止并清理该轮临时产物。

安装包：`build/libs/voxy-distant-0.2.27-forge-1.20.1.jar`，16,643,403 字节；SHA-256 `deb3da8ca39c69ccdac8283ffdd70adee75a4fccf8cb71b2ca3519aca7abcac6`。包内不含 smoke 测试类或 Voxy 类。此次同时修复客户端和服务端，建议两端都更新 VD，继续使用配套 Voxy 0.2.15-beta；不需要清除真实缓存。版本仍兼容协议 17，但旧服务端不会获得原版版本持久失效修复。
