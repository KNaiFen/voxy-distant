# 高速移动后粗 LOD 不恢复：查证与回归

历史验证：2026-10-07，0.2.26 / `dd21d22`。修复已包含在当前源码；后续节点与版本问题见[极端移动报告](extreme-lod-recovery.md)，当前使用说明见[使用指南](../usage.md)。

## 结论与范围

基线为 `7bbfa2e`，修复版本为 `0.2.26-forge-1.20.1`。已确认并修复客户端接收调度、缓存失效同步和请求范围计算中的问题。服务端处理或网络传输滞后可以触发迟到的粗回复，但不足以解释停下以后长期不恢复；客户端原有状态管理确实会丢失刷新需求。

验证采用独立 Forge 客户端与真实专用服务端 socket，配套 Voxy 0.2.15-beta，Java 21.0.7，Embeddium 0.3.31。没有在用户 DeceasedCraft 存档上启动测试，也没有修改该实例的配置、模组或 LOD 缓存。MOD 载具、Iris 光影、Voxy SR 与 Shadows 的组合尚未完整复测，因此不能声称覆盖所有整合包渲染问题。

## 用户实例的只读证据

只读检查的实例为 DeceasedCraft CB 5.11.18，安装 Voxy-distant 0.2.24 与 Voxy 0.2.15-beta。VD 接收开启，Voxy `ingest_enabled=false`，原版渲染距离 10，VD 半径 384、请求窗口 512、接收与索引预算各 512 MiB、处理占空比 0.9。

检查约 66.3 MB 的 `latest.log`，没有发现 `Voxy Distant receive failed` 或异步节点处理线程崩溃。日志包含大量 `Chunk not in map` 与子节点掩码为零的警告；这些警告不能单独证明缓存损坏。日志缺少详细 VD 传输记录，无法从这份日志确定用户现场具体是哪一种时序。

## 原因与最小修复

| 已确认问题 | 触发与后果 | 修复 |
| --- | --- | --- |
| 自动摄入与远程接收错误绑定 | 关闭 Voxy Chunk Ingest 后，即使 VD 接收开启也无法建立会话 | 远程会话只要求 Voxy 渲染开启；其近景快照由接收会话自行采集。单人本地生成保留原摄入开关行为 |
| 重复粗回复无限休眠 | 客户端已经靠近，服务端位置或档位暂时落后，返回相同版本和精度；旧重试截止时间为 `Long.MAX_VALUE` | 复用已有有界退避队列。近景/精度补齐按 2 秒延时重试，普通失败退避上限 16 秒；收到足够精度后清理 |
| 预测范围清掉仍加载区块版本 | 转向后区块暂时落在预测范围外，原版仍加载；版本号被删除后近景 L0 捕获跳过 | 保留 `loadedFull` 内版本，卸载列仍按原范围规则清理 |
| 缓存失效未同步调度目录 | Dirty 已把真实覆盖标为等待刷新，调度目录仍保存旧精度；迟到的目录回复可再次确认旧缓存，吞掉刷新候选 | 限制缓存后，立即以真实目录 Stamp 更新调度目录 |
| 停止后的圆形边界浮点误差 | 斜向移动方向为 `±0.7071067811865475`，预测量归零后仍用椭圆公式；误差漏掉圆边界或同组精度边界 | 预测量为零时直接使用圆的横向投影，避免方向归一化误差，并减少计算 |

无新增常驻线程、配置项、全范围周期扫描或网络协议变更。遮罩改动经过画面对照未显示修复收益，已全部撤回。诊断日志与临时详细反射输出也已移除；只保留回归所需信息。

`ingest_enabled` 对应 Voxy 设置中的 **Chunk Ingest（区块摄入）**，控制自动把客户端已加载区块转换为本地 LOD，并非 VD 的服务器远景接收开关。0.2.24～0.2.25 有上述绑定问题；0.2.26 将两者独立。

## 失败对照与验证结果

原代码在真实客户端的重复 unchanged 粗回复检查中失败：`identical coarse reply must retry while stationary`。修复后无需移动或新的 Dirty 即可再次请求，最终 L0 回复清掉重试。

高速路线中，只有版本号保留修复时停止后仍有 33 列不足，待处理请求与重试均为零。空缓存详细追踪又观察到 21 列不足，其中失效列真实覆盖为 level 5、调度目录仍为旧 L1/L2。同步失效目录后，持久缺口缩小为 3 列；逐列定位发现两列漏掉应有精度、一列未包含在圆形请求范围内。加入实测斜向方向值后，现有扫描掩码参考测试在 `x=0,z=24` 失败；圆形投影修复后通过。

路线坐标为区块 `(24,0) → (24,24) → (-24,24) → (-24,-24) → (24,-24) → (0,0)`。服务端位置采样确认实际经过方块坐标 `x,z ∈ [-384,384]`，客户端预测速度峰值 160。客户端原版距离 10、服务端视距 8、远景半径 24、档位 `8:0,16:1,24:2`、窗口 512、接收预算 128 MiB、索引 256 MiB、处理占空比 0.9；Voxy 8 个服务线程、细分尺寸 64、自动摄入关闭。

已有缓存回归的路线帧采样：1601 帧，平均 13.40 ms、P95 17.87 ms、P99 21.03 ms；接收预留内存峰值 28.25 MiB，队列峰值 273（上限 512），请求峰值 171（窗口 512）。同轮服务端 tick 平均 4.72 ms、P95 13.95 ms、P99 21.96 ms。该轮使用 120 FPS 上限，测试服务端与客户端同机，不能作为修改前后的性能对比，也不代表整合包帧率。算法新增工作限定在失效事件上，圆形分支减少计算，重试保留原窗口与信用限制。

服务端集成测试故意注入配置写入失败、损坏 NBT 和只读数据库错误，并验证失败处理。数据生成烟测中 Voxy 本身的零子节点与 WorldEngine 释放警告为已有基线行为；本轮未据此修改 Voxy 源码。

## 复测方法

保留 `tools/coarse-recovery-check.py` 作为真实客户端回归入口。先用 `./gradlew --no-daemon writeClientLaunch writeSmokeLaunch -PlodClient` 准备启动参数，并按历史环境方式放置 `build/benchmarks/lod-square256-cache128/{client,server}-launch.json`。开发启动参数引用 Gradle 生成的 classpath 文件，运行服务端烟测后需要重新生成带 `-PlodClient` 的启动参数，避免开发依赖模块重复。

输入环境 `build/coarse-recovery-input` 只需要现有测试基线的客户端配置、服务端配置/EULA、`world/level.dat` 与原点四个 region 文件 `r.-1.-1.mca`、`r.-1.0.mca`、`r.0.-1.mca`、`r.0.0.mca`（64×64 区块）。复用测试基线的 EULA；服务端绑定 `127.0.0.1:25576`，离线测试玩家 `LodBench`，不使用真实用户存档。先执行 request，再执行带 `-cold` 后缀的 travel 变体可从空缓存测起；`regression` 变体额外检查两个开关。脚本在 `finally` 中退出客户端和服务端。复测结束需按项目规则删除不再使用的游戏、缓存和原始输出。

```sh
python tools/coarse-recovery-check.py --mode request --variant request-check
python tools/coarse-recovery-check.py --mode travel --variant travel-cold
python tools/coarse-recovery-check.py --mode travel --variant regression
```
